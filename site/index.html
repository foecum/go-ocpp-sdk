Overview

OCPP (Open Charge Point Protocol) is the open standard that charging stations use to talk to the back office that manages them. go-ocpp-sdk lets you build either side: a Charge Point / Charging Station (client) or a Central System / CSMS (server).

⚡

Both roles

One SDK for charging stations and for the central system that manages them.

🔌

OCPP-J only

JSON over WebSocket. SOAP (OCPP-S) is intentionally not implemented.

🧩

Few dependencies

Standard library first. One dependency: coder/websocket, for the transport.

🧪

Tested hard

At least 95% coverage per package, all critical paths covered, tests run with -race.

Pre-1.0OCPP 1.6J is complete: all 28 messages and the 11 of the security extension, the high-level csms and chargepoint APIs, and the WebSocket transport with security profiles 1 to 3. The API may still change before 1.0. OCPP 2.0.1 is in progress: all 64 messages and both high-level APIs exist, see OCPP 2.0.1; examples are next.

Install

shell
go get github.com/foecum/go-ocpp-sdk@latest

Requires a recent Go toolchain (the module targets Go 1.27). Most applications need these packages (the lower-level ocppj and ws are described later):

go
import (
	ocpp "github.com/foecum/go-ocpp-sdk"
	"github.com/foecum/go-ocpp-sdk/chargepoint/v16" // package chargepoint
	"github.com/foecum/go-ocpp-sdk/csms/v16"        // package csms
	"github.com/foecum/go-ocpp-sdk/v16/core"
	"github.com/foecum/go-ocpp-sdk/v16/types"
)

Core concepts

PiecePackageWhat it does
ocpp.Request / ResponseocppA message payload. Reports its Action() and checks itself with Validate().
ocpp.FeatureocppBinds an action name (e.g. "Heartbeat") to its request and response types. Build one with ocpp.NewFeature.
ocppj.RegistryocppjThe set of features for one OCPP version. Decodes and validates payloads.
ocppj.Parse / MarshalocppjConvert between wire frames and Call, CallResult, CallError.
ocppj.EndpointocppjOne side of a connection. Sends calls one at a time, matches replies, times out, and dispatches incoming calls to your handler.
csms.NewcsmsThe Central System: accepts charge points, dispatches their calls to your handler, and lets you call them back.
chargepoint.NewchargepointThe charging station: connects, reconnects, sends typed calls, and answers the Central System through your handler.
v16.NewRegistryv16A registry with every implemented OCPP 1.6 message.
core.BootNotificationRequest …v16/coreThe typed 1.6 Core messages. Shared types and enums are in v16/types.
ws.ServerwsCSMS side of the transport: accepts charge points over WebSocket, authenticates them, negotiates the OCPP version.
ws.ClientwsCharging station side: connects, keeps the connection up and reconnects with back-off.
ws.ConnwsOne live connection. Write fits ocppj.Config.Send.

An Endpoint does no network I/O itself. The transport gives it a Send function and passes every received frame to HandleFrame. That keeps it independent of the WebSocket library, and makes it easy to test in memory. The ws package is the real transport, shown next.

Quick start

This runs a Central System and a charging station in one process, over a real WebSocket on a local port. The station boots, then the Central System resets it.

main.go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"
	"net"

	ocpp "github.com/foecum/go-ocpp-sdk"
	"github.com/foecum/go-ocpp-sdk/chargepoint/v16"
	"github.com/foecum/go-ocpp-sdk/csms/v16"
	"github.com/foecum/go-ocpp-sdk/v16/core"
	"github.com/foecum/go-ocpp-sdk/v16/types"
)

// The Central System answers BootNotification and leaves everything else to
// the embedded handler, which replies NotSupported.
type csmsHandler struct{ csms.UnimplementedCoreHandler }

func (csmsHandler) BootNotification(ctx context.Context, cp *csms.ChargePoint,
	req *core.BootNotificationRequest) (*core.BootNotificationConfirmation, error) {
	fmt.Println("boot from", cp.ID(), "-", req.ChargePointVendor, req.ChargePointModel)
	return &core.BootNotificationConfirmation{
		Status:      types.RegistrationStatusAccepted,
		CurrentTime: types.Now(),
		Interval:    300,
	}, nil
}

// The charging station answers Reset.
type stationHandler struct{ chargepoint.UnimplementedCoreHandler }

func (stationHandler) Reset(ctx context.Context, req *core.ResetRequest) (*core.ResetConfirmation, error) {
	fmt.Println("reset requested:", req.Type)
	return &core.ResetConfirmation{Status: types.ResetStatusAccepted}, nil
}

func main() {
	ctx := context.Background()

	// Central System: an http.Handler, here served on a local port.
	srv, err := csms.New(csms.Config{Core: csmsHandler{}})
	if err != nil {
		log.Fatal(err)
	}
	ln, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		log.Fatal(err)
	}
	go srv.Serve(ln)
	defer srv.Shutdown(ctx)

	// Charging station: connects, and reconnects by itself if the link drops.
	station, err := chargepoint.New(chargepoint.Config{
		URL:  "ws://" + ln.Addr().String() + "/ocpp",
		ID:   "CS001",
		Core: stationHandler{},
	})
	if err != nil {
		log.Fatal(err)
	}
	go station.Run(ctx)
	defer station.Close()
	if err := station.WaitConnected(ctx); err != nil {
		log.Fatal(err)
	}

	// Station -> Central System.
	boot, err := station.BootNotification(ctx, core.BootNotificationRequest{
		ChargePointVendor: "Acme",
		ChargePointModel:  "X1",
	})
	var callErr *ocpp.CallError
	switch {
	case errors.Is(err, ocpp.ErrNotConnected), errors.Is(err, ocpp.ErrTimeout):
		log.Fatal("no answer: ", err)
	case errors.As(err, &callErr):
		log.Fatalf("the Central System answered %s", callErr.Code)
	case err != nil:
		log.Fatal(err)
	}
	fmt.Println(boot.Status, "- heartbeat every", boot.Interval, "s")

	// Central System -> station.
	cp, ok := srv.ChargePoint("CS001")
	if !ok {
		log.Fatal("CS001 is not connected")
	}
	reset, err := cp.Reset(ctx, core.ResetRequest{Type: types.ResetTypeSoft})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("reset:", reset.Status)
}

How a call behaves

  • Only one CALL is outstanding per direction; further calls from other goroutines wait in a queue (default 1000, then ocpp.ErrQueueFull).
  • The response timeout defaults to 30 s, counted from when the call is sent. Set CallTimeout to change it.
  • If your context ends, Call returns ctx.Err() and the next queued call proceeds.
  • Incoming calls run in their own goroutine, so a handler may itself call the peer.
  • With no Handler, or for an action the registry doesn't know, the peer receives a NotImplemented CALLERROR.
  • Close() fails everything pending with ocpp.ErrClosed, cancels running handlers and waits for them.

Central System and Charge Point

Two packages hide the framing, registries and connections. They are csms (import path .../csms/v16) and chargepoint (.../chargepoint/v16).

Central System: csms.New

go
srv, err := csms.New(csms.Config{
	Core:          myHandler,                 // answers charge point calls
	Authenticator: ws.BasicAuthenticator(lookupPassword),
	OnConnect:     func(cp *csms.ChargePoint) {},
	OnDisconnect:  func(cp *csms.ChargePoint, err error) {},
})
log.Fatal(http.ListenAndServe(":8080", srv)) // the CSMS is an http.Handler
// or srv.ListenAndServe(":8080") / srv.Serve(listener), then srv.Shutdown(ctx)

cp, ok := srv.ChargePoint("CS001") // the live connection, if any
ids := srv.ChargePoints()          // connected identities, sorted
  • Charge points connect to ws://host/ocpp/<identity>: the identity is the last path segment of the URL.
  • Typed calls to the charge point, one per Central System message: ChangeAvailability, ChangeConfiguration, ClearCache, DataTransfer, GetConfiguration, RemoteStartTransaction, RemoteStopTransaction, Reset, UnlockConnector (Core), GetDiagnostics, UpdateFirmware, GetLocalListVersion, SendLocalList, ReserveNow, CancelReservation, SetChargingProfile, ClearChargingProfile, GetCompositeSchedule and TriggerMessage. Each takes its request type by value and returns a pointer to the confirmation.
  • A *csms.ChargePoint belongs to one connection. If the station reconnects, look it up again; the old value fails with ocpp.ErrNotConnected. cp.Close() drops the connection.
  • Handlers receive the *csms.ChargePoint, so they can call the station back while handling its request.
  • Other options: TLSConfig (wss, see the security profiles below), CallTimeout, PingInterval, PongTimeout, ReadLimit and Logger.

Charging station: chargepoint.New

go
cp, err := chargepoint.New(chargepoint.Config{
	URL:      "wss://csms.example.com/ocpp",
	ID:       "CS001",
	Password: "…",                          // HTTP Basic auth (profiles 1 and 2)
	Core:     myHandler,                    // answers Central System calls
	OnConnect:    func() {},
	OnDisconnect: func(err error) {},
})
go cp.Run(ctx)             // connects, reconnects with back-off; Close() stops it
err = cp.WaitConnected(ctx)
  • Typed calls to the Central System: Authorize, BootNotification, DataTransfer, Heartbeat, MeterValues, StartTransaction, StatusNotification, StopTransaction, DiagnosticsStatusNotification and FirmwareStatusNotification.
  • The station never sends BootNotification or Heartbeat by itself. Send a BootNotification after each start, and Heartbeats at the interval the Central System returns.
  • Connected() and WaitConnected(ctx) tell you whether the link is up. Other options: Reconnect (see below), TLSConfig, CallTimeout, PingInterval, PongTimeout, ReadLimit and Logger.

Example: smart charging

A station that accepts charging profiles, and a Central System that sets one. The handler field is named after the profile:

go
type stationHandler struct{ chargepoint.UnimplementedSmartChargingHandler }

func (stationHandler) SetChargingProfile(ctx context.Context, req *smartcharging.SetChargingProfileRequest) (*smartcharging.SetChargingProfileConfirmation, error) {
	return &smartcharging.SetChargingProfileConfirmation{Status: types.ChargingProfileStatusAccepted}, nil

station, err := chargepoint.New(chargepoint.Config{
	URL: "ws://csms.example.com/ocpp", ID: "CS001",
	SmartCharging: stationHandler{},

// On the Central System, with cp from srv.ChargePoint("CS001"):
conf, err := cp.SetChargingProfile(ctx, smartcharging.SetChargingProfileRequest{
	ConnectorID: 1,
	CSChargingProfiles: types.ChargingProfile{
		ChargingProfileID:      1,
		ChargingProfilePurpose: types.ChargingProfilePurposeTypeTxDefaultProfile,
		ChargingProfileKind:    types.ChargingProfileKindTypeAbsolute,
		ChargingSchedule: types.ChargingSchedule{
			ChargingRateUnit:       types.ChargingRateUnitTypeA,

		},
	},
})

Logging

Both csms.Config and chargepoint.Config take a *slog.Logger; the default discards everything.

go
logger := slog.New(slog.NewJSONHandler(os.Stderr, &slog.HandlerOptions{Level: slog.LevelDebug}))
srv, err := csms.New(csms.Config{Logger: logger})

When the connection is down

  • A call made while disconnected fails at once with an error matching ocpp.ErrNotConnected. Nothing is queued or retried for you.
  • A call that was waiting for its answer when the connection dropped also returns ocpp.ErrNotConnected straight away, not after the timeout. The other side may or may not have processed it, so only resend what is safe to repeat.
  • OCPP 1.6 requires a station to keep and retry transaction messages (StartTransaction, StopTransaction, MeterValues). Build that on Connected() and WaitConnected(); a ready-made opt-in retry helper is planned.
  • The station reconnects by itself using the back-off from the WebSocket section: Reconnect: ws.Reconnect{WaitMinimum: …, RandomRange: …, RepeatTimes: …}, or leave it zero for the defaults.

Runnable examples

Two programs in examples/v16 talk to each other: a Central System and a simulated charging station. Start the Central System in one terminal:

shell
go run ./examples/v16/csms -addr :8080

and the station in another:

shell
go run ./examples/v16/chargepoint -id CS001

The station boots, sends heartbeats at the interval the Central System returns, and runs charging sessions: authorize, start a transaction, report meter values, stop. The Central System logs everything and calls the station back with GetConfiguration. Its log looks like this (trimmed):

OCPP 1.6 messages

v16.NewRegistry() returns an ocppj.Registry with every implemented message, ready for an Endpoint. The messages live in one package per profile (v16/core, firmware, localauth, reservation, smartcharging, remotetrigger and security); shared types and enumerations live in v16/types.

Naming

Each message is a pair named after the specification: BootNotificationRequest (the .req PDU) and BootNotificationConfirmation (the .conf PDU). In a handler, switch on the request type (*core.BootNotificationRequest) and return the matching confirmation.

Building and validating messages

go
txID := 42
req := core.MeterValuesRequest{
	ConnectorID:   1,
	TransactionID: &txID, // optional numbers are pointers
	MeterValue: []types.MeterValue{{
		Timestamp: types.Now(),
		SampledValue: []types.SampledValue{{
			Value:     "1234.5",
			Measurand: types.MeasurandEnergyActiveImportRegister,
			Unit:      types.UnitOfMeasureWh,
		}},
	}},
}
fmt.Println(req.Validate()) // <nil>

bad := core.StartTransactionRequest{ConnectorID: 0, IDTag: "04A1B2C3", Timestamp: types.Now()}
fmt.Println(bad.Validate()) // ocpp: invalid field "connectorId": must be at least 1, got 0
  • Fields use Go names (ConnectorID, IDTag) and the exact JSON names of the specification on the wire.
  • Optional strings and enumerations are left empty to omit them. Optional numbers and timestamps are pointers, because zero is a real value for them (TransactionID, ReservationID).
  • Every enumeration is a typed string with constants and an IsValid() method, for example types.ChargePointStatusAvailable.
  • types.DateTime wraps time.Time. It is sent in UTC (whole seconds, or milliseconds if present) and accepts what real charge points send: with or without fractional seconds, a Z or an offset, or no zone at all (taken as UTC).
  • Calling Validate() checks required fields, string lengths, ranges and enumeration values. Endpoint.Call does it for you before sending, and the registry does it for every incoming message, answering a bad one with the right CALLERROR code.
  • Rules from the specification text are enforced even where the JSON schema is silent: for example StartTransaction and UnlockConnector need a connector id above 0, MeterValues needs at least one meter value, and the first charging period must start at 0.
  • Unknown JSON properties in incoming messages are ignored rather than rejected, because real charge points send extras. Everything else the official schemas reject is rejected too: the test suite proves it by breaking sample payloads in every way the schemas forbid.
  • Both spellings Celcius and Celsius are accepted as a unit, as the OCPP-J 1.6 errata ask. The errata recommend that charge points keep sending Celcius.
  • Strings are checked for length only; the specification limits them to printable ASCII, but this is not enforced.

Your own messages (vendor extensions through DataTransfer are usually enough, but custom features work too) need Action() and Validate(), and a ocpp:"required" struct tag on every required field so the registry can reject payloads that omit it.

The high-level API has the same shape as the 1.6 one. csms/v201 (package csms) and chargepoint/v201 (package chargepoint) have one handler interface per functional block, set in the matching Config field (Provisioning, Authorization, Transactions, ...), with an embeddable Unimplemented...Handler for each. A block with no handler, or a method you left unimplemented, answers NotSupported. Typed methods call the other side, for example cp.GetVariables on a *csms.ChargePoint or cp.TransactionEvent on a station. A complete program that runs both roles and boots a station:

main.go
package main

import (
	"context"
	"log"
	"net"
	"time"

	ocpp "github.com/foecum/go-ocpp-sdk"
	"github.com/foecum/go-ocpp-sdk/chargepoint/v201"
	"github.com/foecum/go-ocpp-sdk/csms/v201"
	"github.com/foecum/go-ocpp-sdk/v201/provisioning"
	"github.com/foecum/go-ocpp-sdk/v201/types"
)

// handler answers BootNotification; every other call from a station answers
// NotSupported.
type handler struct{ csms.UnimplementedProvisioningHandler }

func (handler) BootNotification(ctx context.Context, cp *csms.ChargePoint,
	req *provisioning.BootNotificationRequest) (*provisioning.BootNotificationResponse, error) {
	log.Printf("%s booted (%s): %s %s", cp.ID(), req.Reason, req.ChargingStation.VendorName, req.ChargingStation.Model)
	return &provisioning.BootNotificationResponse{
		Status:      types.RegistrationStatusAccepted,
		CurrentTime: ocpp.Now(),
		Interval:    300,
	}, nil
}

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 10*time.Second)
	defer cancel()

	srv, err := csms.New(csms.Config{Provisioning: handler{}})
	if err != nil {
		log.Fatal(err)
	}
	l, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		log.Fatal(err)
	}
	go srv.Serve(l)
	defer srv.Shutdown(ctx)

	cp, err := chargepoint.New(chargepoint.Config{URL: "ws://" + l.Addr().String() + "/ocpp", ID: "CS001"})
	if err != nil {
		log.Fatal(err)
	}
	go cp.Run(ctx)
	defer cp.Close()
	if err := cp.WaitConnected(ctx); err != nil {
		log.Fatal(err)
	}
	boot, err := cp.BootNotification(ctx, provisioning.BootNotificationRequest{
		Reason:          types.BootReasonPowerUp,
		ChargingStation: types.ChargingStation{VendorName: "Acme", Model: "X1"},
	})
	if err != nil {
		log.Fatal(err)
	}
	log.Println("boot:", boot.Status, "- heartbeat every", boot.Interval, "s")
}

Security profiles, logging, errors and offline behaviour work as described for 1.6. Constraints that the specification states only in its field tables, and the standardized component and variable names, are not enforced or available as constants yet.

WebSocket transport

The csms and chargepoint packages use this layer for you. Use it directly to build something different. The ws package moves frames over a real WebSocket, for both roles, and plugs into ocppj. This is a complete program: it runs a CSMS and a charging station over a local socket and registers the charge point with a BootNotification.

main.go
package main

import (
	"context"
	"fmt"
	"log"
	"net"
	"sync"

	ocpp "github.com/foecum/go-ocpp-sdk"
	"github.com/foecum/go-ocpp-sdk/ocppj"
	"github.com/foecum/go-ocpp-sdk/v16"
	"github.com/foecum/go-ocpp-sdk/v16/core"
	"github.com/foecum/go-ocpp-sdk/v16/types"
	"github.com/foecum/go-ocpp-sdk/ws"
)

func main() {
	// CSMS: one ocppj.Endpoint per connected charge point.
	var mu sync.Mutex
	endpoints := map[string]*ocppj.Endpoint{}
	srv, err := ws.NewServer(ws.ServerConfig{
		Versions: []ocpp.Version{ocpp.V16},
		OnConnect: func(c *ws.Conn) {
			reg, _ := v16.NewRegistry()
			ep, _ := ocppj.NewEndpoint(ocppj.Config{
				Registry: reg,
				Send:     c.Write,
				Handler: func(ctx context.Context, req ocpp.Request) (ocpp.Response, error) {
					if boot, ok := req.(*core.BootNotificationRequest); ok {
						fmt.Println("boot from", c.ID(), boot.ChargePointModel)
						return &core.BootNotificationConfirmation{
							Status:      types.RegistrationStatusAccepted,
							CurrentTime: types.Now(),
							Interval:    300,
						}, nil
					}
					return nil, &ocpp.CallError{Code: ocpp.NotImplemented}
				},
			})
			mu.Lock()
			endpoints[c.ID()] = ep
			mu.Unlock()
		},
		OnFrame: func(c *ws.Conn, frame []byte) {
			mu.Lock()
			ep := endpoints[c.ID()]
			mu.Unlock()
			ep.HandleFrame(frame)
		},
		OnDisconnect: func(c *ws.Conn, err error) {
			mu.Lock()
			ep := endpoints[c.ID()]
			delete(endpoints, c.ID())
			mu.Unlock()
			ep.Close()
		},
	})
	if err != nil {
		log.Fatal(err)
	}
	ln, err := net.Listen("tcp", "127.0.0.1:0")
	if err != nil {
		log.Fatal(err)
	}
	go srv.Serve(ln)
	defer srv.Shutdown(context.Background())

	// Charging station: a Client that reconnects by itself.
	var station *ocppj.Endpoint
	ready := make(chan struct{}, 1)
	client, err := ws.NewClient(ws.ClientConfig{
		URL:      "ws://" + ln.Addr().String() + "/ocpp",
		ID:       "CS001",
		Versions: []ocpp.Version{ocpp.V16},
		OnConnect: func(*ws.Conn) {
			select {
			case ready <- struct{}{}:
			default:
			}
		},
		OnFrame: func(c *ws.Conn, frame []byte) { station.HandleFrame(frame) },
	})
	if err != nil {
		log.Fatal(err)
	}
	reg, _ := v16.NewRegistry()
	station, _ = ocppj.NewEndpoint(ocppj.Config{Registry: reg, Send: client.Send})
	go client.Run(context.Background())
	defer client.Close()

	<-ready
	resp, err := station.Call(context.Background(), core.BootNotificationRequest{
		ChargePointVendor: "Acme",
		ChargePointModel:  "X1",
	})
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println("registration:", resp.(*core.BootNotificationConfirmation).Status)
}

Server

  • ws.Server is an http.Handler, so you can mount it on any mux, or use Serve / ListenAndServe.
  • The charge point identity is the last path segment of the URL (percent-decoded). It must be 1 to 48 characters with no : or /, otherwise the handshake is answered with 400.
  • The OCPP version is chosen from the client's Sec-WebSocket-Protocol offer, in the order of ServerConfig.Versions. If nothing matches, the handshake completes without a subprotocol and the connection is closed with code 1002, as OCPP-J requires.
  • OnFrame receives frames one at a time per connection, in order, so feeding Endpoint.HandleFrame directly is safe. Keep it quick: it holds up that connection's reads.
  • If a charge point connects again under the same identity, the old connection is closed (code 1008, ws.ErrReplaced) and the new one takes over.
  • Shutdown(ctx) stops accepting, closes every connection with code 1001 and waits. If ctx ends first, the rest are cut.
  • Conn(id) and IDs() look up and list connected charge points.

Client

  • Run(ctx) connects, reconnects after any failure, and returns when ctx ends or Close() is called. Send returns ocpp.ErrNotConnected while disconnected.
  • Reconnecting follows OCPP-J §5.4. The first wait is WaitMinimum plus a random value up to RandomRange. The wait doubles after each failure, up to RepeatTimes times, and starts over after a success. Defaults: 1 s, 2 s and 6 doublings.
  • The identity is appended to ClientConfig.URL, so pass the endpoint URL (wss://csms.example.com/ocpp), not the full connection URL.

Keep-alive

Both sides send WebSocket pings (every 30 s by default, PingInterval; negative disables) and close a connection whose peer does not answer within PongTimeout (10 s). Conn.Err() then reports ws.ErrPingTimeout. Messages larger than 1 MiB (ReadLimit) and binary frames are rejected.

Security profiles

ProfileServerClient
1: Basic auth, ws://Authenticator: ws.BasicAuthenticator(lookup)Password
2: TLS + Basic authProfile 1, plus TLSConfig: ws.ServerTLSConfig(cert, nil)Password, TLSConfig: ws.ClientTLSConfig(rootCAs, nil)
3: TLS + client certificateTLSConfig: ws.ServerTLSConfig(cert, clientCAs) and Authenticator: ws.ClientCertAuthenticator(opts)TLSConfig: ws.ClientTLSConfig(rootCAs, &clientCert)
  • With Basic auth the username is the charge point identity and the password is compared in constant time. The password is the raw UTF-8 string, as OCPP 2.0.1 specifies.
  • An unknown identity gets 404, bad credentials 401, and a certificate that does not match the identity 403.
  • Profile 3 requires the certificate's subject CN to equal the identity. Set ClientCertOptions.Organization to also require the operator name in the subject O, or Identity to use your own rule.
  • TLS 1.2 is the minimum, and only the AES-GCM suites the specification lists (plus the equivalent ECDHE-RSA ones) are enabled. The CSMS certificate is verified through its subjectAltName, as Go requires.
OCPP 1.6 password formatFor OCPP 1.6 the Basic-auth password is the AuthorizationKey: 16 to 20 random bytes written as 32 to 40 hexadecimal digits, sent as that text. ws.BasicAuthenticator compares it as it is. security.GenerateAuthorizationKey() makes a suitable key and security.CheckAuthorizationKey validates one. TLS 1.0 and 1.1, which the whitepaper tolerates for old stations, are not supported: connections need TLS 1.2 or newer.

Working with frames

Endpoints without a transport

An ocppj.Endpoint does no I/O: you give it a Send function and feed it received frames. This program joins two endpoints back to back and needs no network at all, which makes it handy for tests.

main.go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"

	ocpp "github.com/foecum/go-ocpp-sdk"
	"github.com/foecum/go-ocpp-sdk/ocppj"
	"github.com/foecum/go-ocpp-sdk/v16"
	"github.com/foecum/go-ocpp-sdk/v16/core"
	"github.com/foecum/go-ocpp-sdk/v16/types"
)

// newEndpoint creates an OCPP 1.6 endpoint whose frames go to *peer.
func newEndpoint(peer **ocppj.Endpoint, handler ocppj.RequestHandler) *ocppj.Endpoint {
	reg, err := v16.NewRegistry() // every implemented 1.6 message
	if err != nil {
		log.Fatal(err)
	}
	ep, err := ocppj.NewEndpoint(ocppj.Config{
		Registry: reg,
		Handler:  handler,
		Send: func(ctx context.Context, frame []byte) error {
			(*peer).HandleFrame(frame) // a real transport writes to the socket
			return nil
		},
	})
	if err != nil {
		log.Fatal(err)
	}
	return ep
}

func main() {
	var station, csms *ocppj.Endpoint

	station = newEndpoint(&csms, nil)
	csms = newEndpoint(&station, func(ctx context.Context, req ocpp.Request) (ocpp.Response, error) {
		switch r := req.(type) {
		case *core.BootNotificationRequest:
			fmt.Println("boot from", r.ChargePointVendor, r.ChargePointModel)
			return &core.BootNotificationConfirmation{
				Status:      types.RegistrationStatusAccepted,
				CurrentTime: types.Now(),
				Interval:    300,
			}, nil
		case *core.HeartbeatRequest:
			return &core.HeartbeatConfirmation{CurrentTime: types.Now()}, nil
		}
		return nil, &ocpp.CallError{Code: ocpp.NotSupported, Description: req.Action() + " is not supported"}
	})
	defer station.Close()
	defer csms.Close()

	resp, err := station.Call(context.Background(), core.BootNotificationRequest{
		ChargePointVendor: "Acme",
		ChargePointModel:  "X1",
	})
	var callErr *ocpp.CallError
	switch {
	case errors.Is(err, ocpp.ErrTimeout):
		log.Fatal("no answer")
	case errors.As(err, &callErr):
		log.Fatalf("peer said %s", callErr.Code)
	case err != nil:
		log.Fatal(err) // includes validation errors, caught before sending
	}
	boot := resp.(*core.BootNotificationConfirmation)
	fmt.Println(boot.Status, "- heartbeat every", boot.Interval, "s")
}

Frames

Use Parse and Marshal directly if you only need the wire format:

go
msg, err := ocppj.Parse(ocpp.V16, []byte(`[2,"19223201","Heartbeat",{}]`))
if err != nil {
	var pe *ocppj.ParseError
	if errors.As(err, &pe) && pe.ShouldReply() {
		// send a CALLERROR with pe.ID and pe.Code
	}
	return
}
call := msg.(*ocppj.Call) // call.Action == "Heartbeat"

frame, _ := ocppj.Marshal(&ocppj.CallResult{
	UniqueID: call.UniqueID,
	Payload:  []byte(`{"currentTime":"2026-01-01T00:00:00Z"}`),
})
  • Message IDs are at most 36 characters; ocppj.NewUUIDGenerator() makes random UUIDs.
  • If a frame's ID can't be read, the reply uses ID "-1", as the 2.0.1 spec requires.
  • A null payload is accepted and treated as {}.
  • Unknown message types get MessageTypeNotSupported in 2.0.1 and 2.1, and are ignored in 1.6.

Errors

Branch on these with errors.Is / errors.As. Library code never panics on bad input.

ErrorMeaning
ocpp.ErrTimeoutNo response arrived in time.
ocpp.ErrNotConnectedThere is no connection to send on, or it closed while the call waited for its answer.
ocpp.ErrValidationA message failed validation. *ocpp.ValidationError names the field and whether it is missing.
ocpp.ErrCallErrorThe peer replied with a CALLERROR. Use errors.As with *ocpp.CallError for the code, description and details.
ocpp.ErrQueueFullToo many calls are already waiting.
ocpp.ErrClosedThe endpoint was closed.
ocpp.ErrUnknownActionNo feature is registered for that action.
ws.ErrPingTimeoutThe peer stopped answering WebSocket pings (see Conn.Err()).
ws.ErrReplacedThe same charge point connected again; this connection was closed.
ws.ErrNoSubprotocolThe CSMS did not agree to any OCPP version the client offered. The client keeps retrying.
ws.ErrInvalidIDA charge point identity is empty, over 48 characters, or contains : or /.
ws.ErrUnauthorized, ErrUnknownID, ErrForbiddenReturned by an Authenticator to answer the handshake with 401, 404 or 403.

Handlers can return an *ocpp.CallError to choose the CALLERROR sent to the peer; any other error becomes InternalError. Invalid incoming payloads are answered automatically with the right code (TypeConstraintViolation, PropertyConstraintViolation, an occurrence violation for missing fields, or a format violation).
