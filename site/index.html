Overview

OCPP (Open Charge Point Protocol) is the open standard that charging stations use to talk to the back office that manages them. go-ocpp-sdk lets you build either side: a Charge Point / Charging Station (client) or a Central System / CSMS (server).

⚡

Both roles

One SDK for charging stations and for the central system that manages them.

🔌

OCPP-J only

JSON over WebSocket. SOAP (OCPP-S) is intentionally not implemented.

🧩

Few dependencies

Standard library first. Transport and message packages arrive in later phases.

🧪

Tested hard

At least 95% coverage per package, all critical paths covered, tests run with -race.

Pre-alphaThe OCPP 1.6 message types, WebSocket transport and the high-level chargepoint / csms APIs are not written yet. What exists today is the protocol core described below, and its API may still change.

Install

shell
go get github.com/foecum/go-ocpp-sdk@latest

Requires a recent Go toolchain (the module targets Go 1.27). Import the root package and the framing package:

go
import (
	ocpp "github.com/foecum/go-ocpp-sdk"
	"github.com/foecum/go-ocpp-sdk/ocppj"
)

Core concepts

PiecePackageWhat it does
ocpp.Request / ResponseocppA message payload. Reports its Action() and checks itself with Validate().
ocpp.FeatureocppBinds an action name (e.g. "Heartbeat") to its request and response types. Build one with ocpp.NewFeature.
ocppj.RegistryocppjThe set of features for one OCPP version. Decodes and validates payloads.
ocppj.Parse / MarshalocppjConvert between wire frames and Call, CallResult, CallError.
ocppj.EndpointocppjOne side of a connection. Sends calls one at a time, matches replies, times out, and dispatches incoming calls to your handler.

An Endpoint does no network I/O itself. The transport gives it a Send function and passes every received frame to HandleFrame. That keeps it independent of the WebSocket library, and makes it easy to test in memory.

Quick start

This runs a charging station and a CSMS in one process, connected back to back. It uses a made-up Ping message so it works today; the real OCPP messages will plug in the same way.

main.go
package main

import (
	"context"
	"errors"
	"fmt"
	"log"

	ocpp "github.com/foecum/go-ocpp-sdk"
	"github.com/foecum/go-ocpp-sdk/ocppj"
)

// 1. Describe a message: a request and a response type.
type PingRequest struct {
	Message string `json:"message"`
}

func (PingRequest) Action() string { return "Ping" }
func (r PingRequest) Validate() error {
	if r.Message == "" {
		return ocpp.Required("message")
	}
	return nil
}

type PingResponse struct {
	Reply string `json:"reply"`
}

func (PingResponse) Action() string  { return "Ping" }
func (PingResponse) Validate() error { return nil }

// 2. Register it for an OCPP version.
func newRegistry() *ocppj.Registry {
	feature, err := ocpp.NewFeature(PingRequest{}, PingResponse{})
	if err != nil {
		log.Fatal(err)
	}
	reg := ocppj.NewRegistry(ocpp.V201)
	if err := reg.Register(feature); err != nil {
		log.Fatal(err)
	}
	return reg
}

func main() {
	var station, csms *ocppj.Endpoint

	// 3. Create the endpoints. Send is where your WebSocket write goes.
	station, _ = ocppj.NewEndpoint(ocppj.Config{
		Registry: newRegistry(),
		Send: func(ctx context.Context, frame []byte) error {
			csms.HandleFrame(frame) // a real transport writes to the socket
			return nil
		},
	})
	csms, _ = ocppj.NewEndpoint(ocppj.Config{
		Registry: newRegistry(),
		Send: func(ctx context.Context, frame []byte) error {
			station.HandleFrame(frame)
			return nil
		},
		// 4. Handle incoming calls.
		Handler: func(ctx context.Context, req ocpp.Request) (ocpp.Response, error) {
			ping := req.(*PingRequest)
			return &PingResponse{Reply: "pong: " + ping.Message}, nil
		},
	})
	defer station.Close()
	defer csms.Close()

	// 5. Make a call and handle the outcomes.
	resp, err := station.Call(context.Background(), PingRequest{Message: "hello"})
	var callErr *ocpp.CallError
	switch {
	case errors.Is(err, ocpp.ErrTimeout):
		log.Fatal("no answer")
	case errors.As(err, &callErr):
		log.Fatalf("peer said %s", callErr.Code)
	case err != nil:
		log.Fatal(err)
	}
	fmt.Println(resp.(*PingResponse).Reply) // pong: hello
}

How a call behaves

  • Only one CALL is outstanding per direction; further calls from other goroutines wait in a queue (default 1000, then ocpp.ErrQueueFull).
  • The response timeout defaults to 30 s, counted from when the call is sent. Set Config.Timeout to change it.
  • If your context ends, Call returns ctx.Err() and the next queued call proceeds.
  • Incoming calls run in their own goroutine, so a handler may itself call the peer.
  • With no Handler, or for an action the registry doesn't know, the peer receives a NotImplemented CALLERROR.
  • Close() fails everything pending with ocpp.ErrClosed, cancels running handlers and waits for them.

Working with frames

Use Parse and Marshal directly if you only need the wire format:

go
msg, err := ocppj.Parse(ocpp.V16, []byte(`[2,"19223201","Heartbeat",{}]`))
if err != nil {
	var pe *ocppj.ParseError
	if errors.As(err, &pe) && pe.ShouldReply() {
		// send a CALLERROR with pe.ID and pe.Code
	}
	return
}
call := msg.(*ocppj.Call) // call.Action == "Heartbeat"

frame, _ := ocppj.Marshal(&ocppj.CallResult{
	UniqueID: call.UniqueID,
	Payload:  []byte(`{"currentTime":"2026-01-01T00:00:00Z"}`),
})
  • Message IDs are at most 36 characters; ocppj.NewUUIDGenerator() makes random UUIDs.
  • If a frame's ID can't be read, the reply uses ID "-1", as the 2.0.1 spec requires.
  • A null payload is accepted and treated as {}.
  • Unknown message types get MessageTypeNotSupported in 2.0.1 and 2.1, and are ignored in 1.6.

Errors

Branch on these with errors.Is / errors.As. Library code never panics on bad input.

ErrorMeaning
ocpp.ErrTimeoutNo response arrived in time.
ocpp.ErrNotConnectedThere is no connection to send on (returned by transports).
ocpp.ErrValidationA message failed validation. *ocpp.ValidationError names the field and whether it is missing.
ocpp.ErrCallErrorThe peer replied with a CALLERROR. Use errors.As with *ocpp.CallError for the code, description and details.
ocpp.ErrQueueFullToo many calls are already waiting.
ocpp.ErrClosedThe endpoint was closed.
ocpp.ErrUnknownActionNo feature is registered for that action.

Handlers can return an *ocpp.CallError to choose the CALLERROR sent to the peer; any other error becomes InternalError. Invalid incoming payloads are answered automatically with the right code (TypeConstraintViolation, PropertyConstraintViolation, an occurrence violation for missing fields, or a format violation).

Versions & CALLERROR codes

The version constants double as WebSocket subprotocol names.

ConstantValueNotes
ocpp.V16ocpp1.6First target
ocpp.V201ocpp2.0.1Phase 8
ocpp.V21ocpp2.1Later, optional
Spelling differs between versionsOCPP 1.6 uses FormationViolation and OccurenceConstraintViolation (sic); 2.0.1 and 2.1 use FormatViolation and OccurrenceConstraintViolation, and add MessageTypeNotSupported and RpcFrameworkError. ErrorCode.IsValid(version) checks a code against the right set.
